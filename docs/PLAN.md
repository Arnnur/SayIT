# Say IT — план разработки

> «Say it → Live»: айттың — сайт іске қосылды.
> Пользователь описывает сайт голосом или текстом, через 30–60 секунд получает
> опубликованный сайт, ссылку и QR-код.

## 1. Цели и критерии готовности

| # | Требование из ТЗ | Как проверяем |
|---|---|---|
| 1 | Голосовой и текстовый ввод | Кнопка 🎤 (Web Speech API, ru/kk/en), textarea, кнопка «Создать сайт» |
| 2 | Генерация сайта ИИ (дизайн, картинки, адаптив, функции) | Claude пишет один самодостаточный HTML; картинки подставляются по ключевым словам |
| 3 | Индикатор загрузки и статус | Экран загрузки: этапы, прогресс-бар, таймер |
| 4 | Предпросмотр, мобильная версия, открыть в новой вкладке | iframe + переключатель «ПК / планшет / телефон» |
| 5 | Ссылка + QR + копирование + скачивание QR | Блок результата; `GET /api/sites/{id}/qr.png` |
| 6 | Сайт доступен в интернете, а не только в превью | Публикация на Netlify (если задан токен) или раздача самим сервером по `PUBLIC_BASE_URL` |
| 7 | Понятно новичкам | README: как запустить, как устроено, архитектура |

## 2. Стек и почему

| Слой | Выбор | Причина |
|---|---|---|
| Backend | Python 3.11 + FastAPI + Uvicorn | Простой синтаксис, авто-документация `/docs`, async |
| ИИ | Anthropic SDK, модель `claude-opus-5-5`, streaming | Лучшее качество кода; streaming даёт живой прогресс |
| Картинки | Pexels API (если есть ключ) → иначе LoremFlickr по ключевым словам | Работает без ключей, но с ключом — качественнее |
| Публикация | Netlify Deploy API (file digest) → иначе сам сервер `/s/{id}/` | Реальная публичная ссылка для QR |
| QR | `qrcode` + Pillow | PNG без внешних сервисов |
| Frontend | Чистый HTML/CSS/JS, без сборки | Новичку не нужен Node.js/webpack |
| Голос | Web Speech API браузера | Бесплатно, без сервера, поддерживает ru-RU / kk-KZ |
| Тесты | pytest + FastAPI TestClient + httpx.MockTransport | Без реальных сетевых вызовов и без трат на API |

## 3. Архитектура

```
Браузер (static/)                 FastAPI (app/)                          Внешние сервисы
─────────────────                 ──────────────                          ───────────────
index.html  ── POST /api/generate ─▶ main.py ─▶ jobs.JobManager
   ▲                                   │          └─ фоновая задача:
   │  GET /api/jobs/{id} (polling)     │              1. generator.ClaudeGenerator ──▶ Claude API
   └───────────────────────────────────┘              2. images.resolve_images   ──▶ Pexels / LoremFlickr
                                                      3. publisher.publish       ──▶ Netlify / диск
iframe ◀── GET /s/{id}/ (CSP sandbox)                 4. qr.make_qr_png
```

Модули (`app/`):

- `config.py` — настройки из `.env` (dataclass `Settings`).
- `prompts.py` — системный промпт для Claude (требования к дизайну и формату).
- `html_utils.py` — извлечение HTML из ответа модели, `<title>`, валидация.
- `images.py` — плейсхолдеры `{{IMAGE:запрос|ШxВ}}` → реальные URL.
- `generator.py` — вызов Claude (streaming, прогресс, обработка отказа/обрыва).
- `publisher.py` — `LocalPublisher` (диск + `/s/{id}/`) и `NetlifyPublisher`.
- `qr.py` — генерация QR в PNG и data URL.
- `jobs.py` — хранилище задач и конвейер «генерация → картинки → публикация → QR».
- `rate_limit.py` — ограничение частоты запросов по IP.
- `main.py` — FastAPI-приложение (`create_app`) и маршруты.

## 4. API

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/` | Интерфейс сервиса |
| `GET` | `/api/health` | Проверка: жив ли сервер, какой публикатор активен |
| `POST` | `/api/generate` | `{ "prompt": "..." }` → `202 { "job_id" }` |
| `GET` | `/api/jobs/{job_id}` | Статус: `queued / generating / images / publishing / done / error`, `progress`, `result` |
| `GET` | `/api/sites/{site_id}/qr.png` | QR-код для скачивания |
| `GET` | `/s/{site_id}/` | Опубликованный сайт (локальная публикация) |

Почему polling, а не WebSocket/SSE: проще для новичков, работает за любым прокси,
легко тестируется. Опрос раз в секунду — нагрузка ничтожная.

## 5. Безопасность

- Сгенерированный HTML отдаётся с заголовком `Content-Security-Policy: sandbox ...`
  и показывается в `<iframe sandbox>` — его JavaScript не получает доступ к origin сервиса.
- `site_id` проверяется регуляркой — нет path traversal.
- Длина промпта ограничена (3–2000 символов), лимит запросов по IP, лимит параллельных задач.
- Ключи только в `.env` (в `.gitignore`), есть `.env.example`.

## 6. Скорость (цель 30–60 с)

- Streaming: прогресс виден сразу.
- `effort` по умолчанию `low` — меньше «раздумий», быстрее ответ (настраивается).
- Опциональный fast mode (`CLAUDE_FAST_MODE=true`, до 2.5× быстрее, дороже).
- Промпт просит компактный, но полный одностраничный сайт.

## 7. План тестов (пишем до реализации)

| Файл | Что проверяем |
|---|---|
| `test_html_utils.py` | извлечение HTML из ```-блоков и текста, `<title>`, ошибка без HTML |
| `test_images.py` | поиск плейсхолдеров, fallback URL, Pexels через mock, дубликаты, сбой Pexels |
| `test_publisher.py` | локальная запись файла и URL; Netlify: создание сайта, deploy, upload; ошибки |
| `test_qr.py` | PNG-сигнатура, data URL |
| `test_rate_limit.py` | лимит, окно времени, разные IP |
| `test_generator.py` | параметры запроса (модель, effort, fallbacks, fast mode), стрим, отказ модели |
| `test_api.py` | полный сценарий через API с фейковым генератором, CSP-заголовок, 404/422/429, ошибка генерации |

## 8. Этапы и коммиты

1. `docs: план проекта` — этот файл.
2. `test: тесты до реализации` — красные тесты, фиксирующие поведение.
3. `feat: базовые модули` — config, html_utils, images, qr, rate_limit.
4. `feat: публикация` — local + Netlify.
5. `feat: генератор Claude и конвейер задач`.
6. `feat: FastAPI API`.
7. `feat: интерфейс` — главная, загрузка, результат, голос.
8. `docs: README` — запуск, архитектура, FAQ для новичков.

## 9. Возможные улучшения (после MVP)

- Редактирование сайта голосом («сделай фон темнее») — повторный запрос с текущим HTML.
- Публикация на GitHub Pages как альтернатива Netlify.
- Хранение задач в SQLite/Redis вместо памяти (переживает перезапуск).
- Серверное распознавание речи для браузеров без Web Speech API.
